# 🚀 Watermark ETL — Быстрое обновление данных

## 📋 Что такое Watermark

**Watermark** — это время последнего успешного запуска ETL. Скрипт выгружает **только изменения** с момента последнего запуска, а не все данные за 3 дня.

---

## ⚙️ Как это работает

### 3-дневный цикл (каждые 10 минут)

```python
# 1. Получаем время последнего запуска
last_run = get_watermark('ORDER_DETAIL')  # например, 2026-03-25 10:00:00

# 2. Выгружаем ТОЛЬКО изменения
SELECT * FROM ORDER_DETAIL
WHERE DATE_TIME_STAMP >= @last_run  # только новые/изменённые с 10:00

# 3. Вставляем/обновляем в target
INSERT INTO raw_.ORDER_DETAIL VALUES (...)

# 4. Обновляем watermark
set_watermark('ORDER_DETAIL', datetime.now())  # 10:10:00
```

**Результат:**
- ✅ Выгружается 1-5K строк вместо 100K
- ✅ Время: 10-30 сек вместо 1-3 мин
- ✅ Минимальная нагрузка на источник

---

### 7-дневный цикл (ежедневно в 23:59)

```python
# Полная выгрузка за 7 дней (как раньше)
SELECT * FROM ORDER_DETAIL
WHERE DATE_TIME_STAMP >= DATEADD(DAY, -7, GETDATE())

# Полная перезапись
DELETE FROM raw_.ORDER_DETAIL WHERE date >= @cutoff
INSERT INTO raw_.ORDER_DETAIL SELECT ...
```

**Результат:**
- ✅ Гарантия актуальности (все данные за 7 дней)
- ✅ Перекрывает пропущенные изменения

## 📊 Таблица watermark

Скрипт автоматически создаёт таблицу `etl.watermark`:

```sql
CREATE TABLE etl.watermark (
    table_name NVARCHAR(100) PRIMARY KEY,
    last_run_time DATETIME NOT NULL,       -- Время запуска
    last_success_time DATETIME NULL,       -- Время последнего успеха
    rows_processed INT NULL,               -- Сколько строк обработано
    created_date DATETIME DEFAULT GETDATE(),
    modified_date DATETIME DEFAULT GETDATE()
);
```

**Просмотр watermark:**
```sql
SELECT 
    table_name,
    last_run_time,
    last_success_time,
    rows_processed,
    DATEDIFF(MINUTE, last_run_time, GETDATE()) AS minutes_ago
FROM etl.watermark
ORDER BY table_name;
```

## ⚠️ Важные нюансы

### 1. Что если запись изменилась 11 минут назад?

**Проблема:** Если ETL запускается каждые 10 минут, а запись изменилась 11 минут назад — пропустим.

**Решение:** 7-дневный цикл в 23:59 перекроет все пропущенные изменения.

---

### 2. Что если DATE_TIME_STAMP не обновляется?

**Проблема:** Если `DATE_TIME_STAMP` — это дата создания, а не модификации.

**Решение:** 7-дневный цикл полностью перезаписывает данные.

**Проверка:** Выполните эксперимент из `README_WATERMARK.md`.

---

### 3. Что если скрипт упал с ошибкой?

**Проблема:** Watermark не обновился, следующий запуск выгрузит те же данные.

**Решение:** Это правильное поведение! Данные будут выгружены при следующем запуске.

## 🔍 Мониторинг

### Проверка последнего запуска
```sql
SELECT 
    table_name,
    last_success_time,
    rows_processed,
    DATEDIFF(MINUTE, last_success_time, GETDATE()) AS minutes_ago
FROM etl.watermark
WHERE last_success_time IS NOT NULL
ORDER BY minutes_ago DESC;
```

### Проверка проблемных таблиц
```sql
SELECT 
    table_name,
    last_run_time,
    last_success_time,
    CASE 
        WHEN last_success_time IS NULL THEN '❌ Ни одного успеха'
        WHEN DATEDIFF(MINUTE, last_success_time, GETDATE()) > 30 THEN '⚠️ Не обновлялось >30 мин'
        ELSE '✅ OK'
    END AS status
FROM etl.watermark
ORDER BY table_name;
```
